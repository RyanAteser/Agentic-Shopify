# Merchant-authorized product-page Search Console reporting

**Status:** implemented as a manually triggered, read-only Google import in Artemis SEO Intelligence. This is a reporting workflow, **not a claim of SEO performance improvement**. No Google token is configured or connected to the current development store.

## User journey

1. The Shopify merchant opens **Verified Growth** and explicitly authorizes their own exact HTTPS URL-prefix Search Console property using the existing `webmasters.readonly` Google OAuth flow. This does not grant write scopes.
2. In **SEO Intelligence**, Artemis confirms the current primary domain through Shopify Admin GraphQL and checks that the saved Google property is exactly `https://<primary-host>/`. Inactive, legacy domain-property or cross-store GSC connections are refused.
3. Only if the Shopify catalog returns public, canonical HTTPS URLs on that primary host, the merchant can click **Import product-page metrics (read-only Google)**. The button is not available when the storefront URL sample is empty or protected.
4. The app requests up to **12 product pages** selected from Shopify's bounded first 100 active Online Store products. It does not construct URLs for password-protected products, ingest competitor URLs, or access customer data. An hourly import lock prevents accidental API bursts.
5. The report displays each product's observed Search Console date-row count (out of 56 possible Pacific reporting dates), clicks, impressions and observed CTR. Missing rows are **unobserved**, not zero. Page metrics are kept separate from the property-wide growth metrics.
6. A successful but empty Google snapshot clears stale rows and displays “no observed page/date rows”, not zero traffic or a clean SEO score. All reports remain descriptive.

## Scope, API and limits

The only Google API operations are OAuth refresh token exchange and the Search Analytics POST endpoint using the **existing read-only consent**. For each Shopify-verified URL the request uses:

```json
{
  "dimensions": ["date", "page"],
  "type": "web",
  "dataState": "final",
  "aggregationType": "byPage",
  "dimensionFilterGroups": [{
    "groupType": "and",
    "filters": [{
      "dimension": "page",
      "operator": "equals",
      "expression": "THE EXACT MERCHANT-SCOPED PRODUCT URL"
    }]
  }],
  "rowLimit": 100,
  "startRow": 0
}
```

The actual date window is generated by `gscReportingWindow()`: 56 Pacific calendar days ending three days before the sync date. There can be at most 56 unique product/date rows for one page. Reject wrong aggregation types, duplicate/out-of-range dates, canonical URL mismatches, malformed counts, incomplete-data metadata and oversized results rather than silently blending one page into another.

Google Search Console can omit low-volume data, privacy-filtered queries and dates without observations, and search pages may use Google-selected canonical URLs. Exact-page filtering can therefore return no rows for a real Shopify URL; absence is not evidence of zero demand. Documentation: [Google Search Analytics API](https://developers.google.com/webmaster-tools/v1/searchanalytics/query).

## Persistence, tenant safety and consent revocation

New table `GscProductDailyMetric` stores `shop, property, pageUrl, date, clicks, impressions, ctr, position` and an import time, with a uniqueness constraint on all four identifying fields. No shopper, customer, OAuth token or query string is stored in this table.

- An authenticated Shopify session supplies `shop`; GraphQL attests `shop.myshopifyDomain` and `primaryDomain.host`. The browser cannot choose a property, shop, page URL or access token.
- Google access starts only after an explicit POST form action and an active matched connection is atomically leased. The page import lease is separate from the property-wide sync lease; failed imports release it.
- All Google results for the bounded sample must validate before any metric is committed. The final database transaction locks/revalidates the same connection, refresh credential and lease; it then atomically replaces that shop's prior page sample. A disconnect/re-consent during the fetch cannot resurrect revoked data.
- Re-consenting to Google clears old page metrics and both page-sync timestamps. Disconnect erases metrics, state and credential, as does the existing merchant redaction/uninstall path.
- Persistent metrics are **not** evidence of a controlled SEO experiment. No intervention history, treatment/control assignment, query-matched measurement, significance test or attributable revenue is implied.

**Deployment:** Additive PostgreSQL migration `20261102190000_gsc_product_daily_metrics` must be applied with `prisma migrate deploy --schema prisma/schema.postgresql.prisma`; local SQLite development uses `prisma db push` and `prisma generate`. No migration was applied to an external production database during development.

## Validation

```bash
node --import tsx --test --test-concurrency=1 tests/gsc-product-page-metrics.test.ts tests/gsc-product-page-import.test.ts
npm run typecheck
npm test
npm run build
```

The integration tests mock Shopify Admin and Google responses while using local/CI databases. They exercise successful scoped imports, hourly rate limiting, stale snapshot removal, malformed second-page failure/atomic rollback, external merchant URL exclusion, disconnect during an in-flight import, and re-consent cleanup. The PostgreSQL CI job validates the additive migration and safety boundaries.

**Current store:** The Artemis development storefront remains password-protected and returned 13 sampled active products with null `onlineStoreUrl`, and its database has no Search Console connection. A live Google page import **cannot** be run there until a merchant authorizes a matching property and Shopify reports real public product URLs.
